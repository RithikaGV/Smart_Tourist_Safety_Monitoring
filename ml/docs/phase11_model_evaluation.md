# Phase 11 — Model Evaluation Summary

All 6 AI modules evaluated together. Read the caveats section — it applies
to every number in this document.

---

## 1. Risk Prediction (Module 1) — XGBoost, supervised

| Metric | Value |
|---|---|
| Accuracy | 0.917 (+/- 0.091) |
| Precision (Dangerous) | 0.850 (+/- 0.300) |
| Recall (Dangerous) | 0.800 (+/- 0.245) |

**Evaluated on:** 60 places, only 9 labeled "Dangerous" — small sample,

**Biggest gap:** weather features currently show 0.000 importance — real
weather data hasn't been merged in yet (needs Colab pipeline).

## 2. Safety Score (Module 2) — Weighted formula, v1

No accuracy/precision applies — this is a transparent formula, not a
trained model (deliberate choice, see Phase 6 notes). Sanity-checked
instead: all 4 restricted zones correctly landed at the bottom of the
score range (35.2–41.0), non-restricted places scored higher (up to
73.7). Directionally correct; exact ranking among safe places still
depends on placeholder hospital-distance data.

## 4–6. Unsupervised modules — comparison table

| Module | Algorithm | Capture Rate | Precision-like | Lift vs random | Tourists flagged |
|---|---|---|---|---|---|
| Behaviour Analysis | DBSCAN | 70.8% | 26.0% | 4.0x | 177 |
| Suspicious Movement | Isolation Forest | 67.7% | 44.0% | 6.8x | 100 |
| Pattern Detection | Isolation Forest (sequence features) | 66.2% | 56.6% | 8.7x | 76 |

**Winner by precision: Pattern Detection.** Using sequence/order-based
features (repeated restricted-zone entries, back-and-forth alternation)
beat both aggregate-stat approaches (DBSCAN, Suspicious Movement) on
precision, while giving up very little capture rate. If only one
unsupervised module had to be prioritized for further development, this
comparison supports Pattern Detection.

**All three flagged fewer people as we added better features** — 177 →
100 → 76 — while capture rate stayed roughly flat (~67-71%). That's a
real, meaningful trend: better features reduce false alarms without
meaningfully sacrificing detection.

## THE CAVEAT THAT APPLIES TO EVERYTHING ABOVE

Every "suspicious" and "dangerous" label used to compute these numbers
was **generated by a rule we wrote ourselves** (see
`generate_risk_labels.py` and the `is_suspicious_tourist` logic in
`generate_synthetic_data.py`), not observed from real incidents.

This means every number above measures **"how well did the model learn
to reproduce our own synthetic rule,"** not **"how well would this catch
real dangerous places or real suspicious tourists."** These are useful,
honest results for proving the pipeline works end-to-end — they are not
evidence of real-world accuracy, and should never be presented as such
without this caveat attached.

## What's genuinely proven at this point
- Every module runs end-to-end without errors, on real code, on real
  (partially verified) geography
- Every trained model is properly saved and reloadable without retraining
- The unsupervised modules show real, consistent signal (well above
  random chance) on the synthetic ground truth
- Feature quality clearly matters — the comparison table above is real,
  useful evidence for that specific claim

## What's still needed before any of this is trustworthy
1. Real weather + emergency-service data merged in (Colab pipeline)
2. Real ground truth of any kind — even a small hand-labeled set of
   genuinely risky Nilgiris locations, or documented past incidents,
   would be far more valuable than more synthetic tuning
3. More Dangerous examples for Risk Prediction (9 is too few for stable evaluation)
